                              API ENDPOINTS
═══════════════════════════════════════════════════════════════════════════════

START SESSION:
  POST /api/reflection/start
  Input:  { sessionMode: "guided" | "quick" }
  Output: { sessionId, mode, message }

SEND MESSAGE:
  POST /api/reflection/message
  Input:  { sessionId, message }
  Output: { message, type, duration, suggestEnd, ... }

END SESSION:
  POST /api/reflection/end
  Input:  { sessionId }
  Output: { sessionId, status, duration, messageCount }

GET INSTRUCTIONS:
  GET /api/reflection/instructions
  Output: { identity, purpose, scope, safety, ... }

═══════════════════════════════════════════════════════════════════════════════
                            DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════════════════

✓ Bounded sessions (not endless chat)
  Reason: Prevents dependency, respects user autonomy

✓ Session-based memory (not persistent)
  Reason: Privacy-first, prevents over-reliance

✓ Pattern-focused conversation
  Reason: Conversation serves data engine

✓ Immediate crisis escalation
  Reason: User safety over engagement

✓ Transparent system instructions
  Reason: Users can see what Claude knows

✓ Voice integration
  Reason: Accessibility, natural interaction

✓ Per-session storage (in-memory)
  Reason: Privacy, simplicity, scale later
